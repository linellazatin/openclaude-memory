# AGENTS.md

OpenCode plugin injecting persistent markdown memory into agent system prompts. Plain ESM JavaScript — no TypeScript, no bundler, no lint, no formatter, zero runtime dependencies.

## Commands

```sh
npm test                              # 120 sequential smoke checks plus real-process shared writers
npm run test:host                     # real OpenCode 1.18.34 server with a local fake model
node tests/shared-store-test.mjs /absolute/path/to/openpi-memory/extensions/memory-core.mjs
for file in .opencode/plugins/*.mjs tests/*.mjs; do node --check "$file" || exit; done
npm install                           # run INSIDE .opencode/ to get @opencode-ai/plugin type hints (see Two package.json files)
```

No build / typecheck / lint / format command exists. There is no way to run a single test: `smoke-test.mjs` runs the whole sequential suite (`node:assert`, no test runner).

## Key paths

| Path | Role |
|------|------|
| `.opencode/plugins/ocl-memory.mjs` | Server plugin — hooks, 4 tools (`write_memory`/`remove_memory`/`pin_memory`/`repair_memory`), injection, consolidation. Published entry `exports["."]`. |
| `.opencode/plugins/ocl-memory-shared.mjs` | Pure-logic module (NO plugin hooks) shared by both plugins — path/config resolution, `withLock`/`acquireLock`/`releaseLock` + `LockContendedError`, atomic writes, carry-over, `parseIndexLine`, `isSafeFilename`. |
| `.opencode/plugins/ocl-memory-tui.mjs` | TUI plugin (`exports["./tui"]`), registered in the user's `tui.jsonc`. |
| `.opencode/command/memory.md` | Static `/memory` fallback (LLM-rendered); dynamic registration overrides it at runtime. |
| `skills/memory/SKILL.md` | Memory skill loaded on-demand by agents. Carries its own `version:` frontmatter. |
| `tests/smoke-test.mjs` | 120 smoke checks; sequential order is load-bearing. |
| `tests/shared-store-test.mjs` | Real-process OpenCode/OpenCode writers; optional pi core path verifies cross-harness storage. |
| `tests/host-test.mjs` | Real OpenCode 1.18.34 server with a local fake model; tools, request injection, sessions, and consolidation. |
| `package.json` | Root manifest, published to npm; `files: ["skills/", ".opencode/"]`. |
| `.opencode/plans/` | Research/planning docs — NOT implementation specs, and gitignored (never committed). |
| `docs/` | User-facing prose docs (architecture, configuration, faq, memory-injection, shared-directory). Behavior-coupled — update when plugin behavior changes. |

`AGENTS.md`, `CLAUDE.md`, and `plans/` are all in the root `.gitignore`, so edits to them will NOT show up in `git status`. This is expected — do not chase it.

## Architecture

- Two plugin *entry-point* files must stay separate: opencode's type system enforces `TuiPluginModule.server?: never` and `PluginModule.tui?: never`. `ocl-memory-shared.mjs` is exempt because it exports no hooks — importing it from both entry points is fine.
- Storage: index at `~/.config/opencode/memory/MEMORY.md` (or `~/.agents/memory/` when `shared_dir`), config at `~/.config/opencode/memory.jsonc`. All resolved from `XDG_CONFIG_HOME`/`os.homedir()` at module load.

## Conventions & invariants (each was a real bug; do not "simplify" away)

- **No zod — flat args map required.** `args` are plain JSON Schema, one entry per param: `{ topic: {type:'string'}, ... }`. opencode's `legacyJsonSchema()` fallback (used when no Zod marker is present) needs a FLAT map. Wrapping in `{ type:'object', properties:{...} }` makes `type`/`required`/`properties` be read as param names and every real arg arrives `undefined` — this was the 0.5.1 production outage.
- **Tool arg guards return a string, never throw.** Validate `topic` as a non-empty string and `content`/`summary` as strings before string operations. Empty content/summary are permitted; filesystem failures may throw. `repair_memory` takes no args. Native flat-schema calls must supply `pin` and `mode` explicitly despite their direct-JS defaults.
- **`pin` coerced via `pin === true || pin === 'true'`, not JS truthiness.** A string `"false"` is JS-truthy and used to mean "pin"; the coercion fixes it while keeping `"true"` working. Applied in `write_memory` and `pin_memory`.
- **`findIndexEntry` is exact-wins / ambiguous-refuses** (openpi-memory parity): an exact case-insensitive name-or-filename match returns outright; otherwise a single substring match is returned, and MULTIPLE substring matches return `{ambiguous, names}` → `remove_memory`/`pin_memory` refuse without touching anything. Never regress to first-substring-wins: it silently mutates whichever similar topic happens to sort first.
- **`write_memory` collapses + caps `summary` at 500 chars** (`MAX_SUMMARY_LENGTH`, openpi parity) into `cleanSummary` BEFORE its first use, so frontmatter description, index line, and the result message all carry the identical value; a rambling summary can't eat the 50 KB injection budget.
- **`isSafeFilename()` guards filenames read back from `MEMORY.md`.** `toSlug()` only sanitizes NEW write-path filenames (strips everything outside `[a-z0-9\s-]`); it is never a validator on read. A corrupted / untrusted-co-tenant index line can otherwise flow `../../../etc/passwd` into `path.join`. Applied at every read-time path boundary: `write_memory` (rejects unsafe same-topic entry before `topicPath`), `remove_memory` (refuses + returns error), `maintainIndex` and `mergeLocalIntoSharedDir` (drop like an orphan), TUI `parseIndex` (hides) + TUI read/mutate (refuse). No need to re-check inside `resolveDestName`/`filesEqual` — their sole caller already validated. As of 0.6.5 it ALSO rejects a leading `.` (hidden/tool-internal files: `.ocl-removed`, `.lock`, dotfiles) and any `[]()` (which break the `- [name](filename)` index shape). `write_memory` now guards its own generated slug with `isSafeFilename` too, so a punctuation-only topic name (→ `.md`) is rejected with a clean error instead of writing a file the read-back guard would then silently orphan.
- **`write_memory` slug-collision fallback.** If a NEW topic's slug hits an existing file owned by a DIFFERENT topic (`!matchedExisting`), bump `-2`, `-3`, ... until free BEFORE touching the file — pre-fix this appended one topic's content into another's and relabelled the shared index line (cross-topic corruption). A legitimate re-write of the same name matches by name and reuses the file (no false-positive suffix bump).
- **Intentional removals are tombstoned in `.ocl-removed`.** Record intent before deleting index references; preserve the topic file. Repair and migration skip tombstones. Re-store reclaims a tombstoned file only when its frontmatter name matches the requested topic; unrelated slug owners get a numeric suffix. Clear the tombstone only after successful publication. The active directory's list is shared with pi and every mutation stays inside `withLock`. Do not treat mere tombstone presence as permission to overwrite an unrelated topic.
- **`stripJsonc` is string-literal-aware.** A naive `//`-strip regex truncates any config value containing `//` (e.g. a URL), corrupting the JSON; `parseRules`/`renderRulesForInjection`'s catch then silently resets config to defaults. Do NOT revert to a two-regex one-liner. `parseRules` and `readMemoryRules` now `console.error` before falling back. As of 0.6.5 the char loop also strips `/* … */` block comments (string-literal-aware, so a `*/` inside a glob value is safe); before this a valid-JSONC block comment made the whole file fail to parse and silently revert to defaults.
- **Index lines are one physical record — `sanitizeIndexField` enforces it.** A `MEMORY.md` topic = a single `- [name](file.md) date -- summary` line. `sanitizeIndexField` (in `ocl-memory.mjs`) collapses `\r\n` to spaces and strips `[]()` on the two free-text fields that reach the line (`upsertIndexLine`'s `name`/`summary`; `repairMemoryIndex`'s recovered `fm.name`/`description`, whose `fm.ts` is also newline-stripped in `readFrontmatter`). Without it a newline in a `summary` splits one record into two lines and a crafted summary injects a phantom entry — a real hazard under `shared_dir` where foreign index lines are trusted on read. `write_memory` sanitizes `topic` (→ `cleanTopic`) ONCE at the top of `execute()` so slug, exact-name match, frontmatter `name:`, and the index line all use the same clean value; do not reintroduce a raw-`topic`/`cleanTopic` mismatch. Topic-file *content* is NOT sanitized (newlines there are normal markdown).
- **50 KB injection cap is enforced line-by-line.** `readMemoryIndex()` reserves room for the warning and keeps only whole lines fitting `MAX_BYTES`; never `lines.slice(0, maxLines)` after a byte-overflow — one giant line defeats it.
- **`readMemoryIndex()` never writes on the read path.** When `MEMORY.md` is absent it returns `INITIAL_MEMORY` in-memory only; it must NOT create the file. `getCache()` calls it every turn (unlocked), so creating it there was the last unlocked write under `shared_dir` and could clobber a co-tenant's brand-new index. The file is created only by the locked tool paths (`write_memory`) and locked carry-over/merge. Consequence: a fresh install materializes `MEMORY.md` on the first real write, not on first session load.
- **`write_memory` append-mode timestamp bump is frontmatter-scoped.** Both `append` and `replace` first extract the `^---\n...\n---\n` frontmatter block and run the `last_updated:`/`created:` regex ONLY on that block. Do NOT revert append to matching against the whole file (`existing.includes` + `/m` `existing.replace`): a topic-file body line beginning `last_updated:` would be rewritten and the frontmatter never stamped.
- **Two `package.json` files.** Root is published. `.opencode/package.json` is gitignored (by `.opencode/.gitignore`, which also ignores `node_modules`, `bun.lock`) and never published — it exists only for `@opencode-ai/plugin` type hints. Run `npm install` in `.opencode/`.

## shared_dir, locking, cache

- **`memory.jsonc` is the single local config source.** Publish a missing config exclusively before renaming legacy `memory/RULES.jsonc` to `.bak`. Preserve a racing creator's config and existing backups; failed publication leaves the legacy original intact. JSONC comments and trailing commas must remain string-literal-aware.
- **`getMemoryDir(config)`/`getMemoryIndex(config)` resolve the active directory.** Capture it before acquiring the mutation lock. File-stamp checks detect config/path changes before server cache reuse; the TUI resolves config on each open and dynamic `/memory` refreshes before execution. No restart is required for ordinary config/index edits.
- **Carry-over is merge-aware + double-guarded.** `maybeCarryOverToSharedDir()` (async) runs at most once *ever* per install: `_carryOverChecked` short-circuits within a process *only after a fully successful merge* (a failed/lock-contended attempt retries on the next cache refresh), and `CARRY_OVER_SENTINEL` (`.shared-dir-migrated` in local `MEMORY_DIR`, written only after success) short-circuits across process starts, turning the O(n) scan into one `fs.existsSync`. It MERGES (never skips just because shared `MEMORY.md` exists — that orphaned local memory if openpi-memory wrote first): per local index entry → copy under original name; identical content → skip; different content → `-oclm` suffix (`-oclm-2`... if needed). An identical pre-existing shared file still gets its missing index line appended so it stays discoverable. One-way: originals are copied, not moved; toggling off→on does not re-run or reconcile drift. `parseIndexLine`/`INITIAL_MEMORY` live in the shared module for this.
- **`withLock` is the single mutation entry point, fail-closed in both modes.** Local acquisition waits about 500 ms; shared uses 2 s, a 1 s delay, and another 2 s window before `LockContendedError`/`BUSY_MESSAGE`. Capture each acquisition's token synchronously before awaiting; an old call must not release a newer same-process lock. Release verifies the captured token, stale reclaim verifies PID liveness and unchanged inode/mtime, and `EPERM` means alive. Failed stale unlink must still obey the deadline. Unknown payloads use the 60 s hard threshold. The compatible protocol has no atomic compare-and-unlink; do not describe these checks as a strict filesystem lease guarantee.
- **Repair is additive-only and idempotent.** Scan safe regular `.md` files missing from the index and removal list, then append `[stale?]` entries dated from frontmatter. Decode quoted fields; sanitize every emitted field and fall back to a usable filename when the name becomes empty. Never delete/reorder existing entries. Report the pre-existing indexed count separately from added entries. Shared drift notes trigger above five missing non-tombstoned topics; never auto-repair a co-tenant's possible in-flight write. Memory tools invalidate the cache.
- **Recap topic is `ocl-last-session-recap.md` (`"OCL Last Session Recap"`), NOT `last-session-recap`.** openpi-memory reserves `last-session-recap` and its `retireRecapEntries()` strips that exact index line from the shared dir every session — so our recap MUST use the `ocl-`-namespaced slug or openpi silently deletes it. The display name is chosen so `toSlug("OCL Last Session Recap")` yields exactly `ocl-last-session-recap` — do NOT rename it back to a parenthetical like "Session Recap (openclaude)", whose slug (`session-recap-openclaude`) differs, and which once let consolidation spawn two divergent "recap" topics. Set in both `CONSOLIDATION_PROMPT` and `buildCompactConsolidationPrompt`.
- **Topic frontmatter uses quoted names/descriptions** via `JSON.stringify`. Both write modes refresh these fields and `last_updated`, preserving `created` and unknown fields. Migration compares whole-file bytes, not semantic frontmatter equality. Collision suffix stays tool-private: ours `-oclm`, pi's `-opim`.
- **`.invalidate` is computed from the active directory and never consumed.** TUI writes it atomically; every server cache compares its stamp independently. Config, directory, index, and tombstone stamps detect ordinary manual/co-tenant edits too. Notification failure must report that the index mutation already committed.

## Injection & consolidation

- **Per-file durability and recovery.** No-follow reads verify regular descriptors; UI/injection reads are bounded before allocation. Atomic writes use exclusive temporary files, flush data, and clean temporary files. Ordinary topic/index publication failures attempt rollback, reporting affected paths if rollback also fails. Directory entries are not fsynced; abrupt termination is not a transaction and may leave recoverable drift. Metadata refresh remains frontmatter-scoped and preserves creation/unknown fields.
- **Reads must not block on special files.** Use nonblocking open before verifying regular descriptors. Store reads reject final-component symlinks; trusted config symlinks are supported, with target stamps included in cache freshness. Behavioral rules render non-empty arrays, falling back to raw config when parsing fails or no non-empty arrays exist.

- **Always attach memory/rules in `experimental.chat.system.transform`.** OpenCode constructs fresh output for each model request, including other sessions and internal calls. No first-turn/dirty gate is valid. `_requestCount` and `inject_every_n_turns` control forced disk refreshes, not injection or prompt-token savings. Cache signatures independently detect config, directory, index, tombstone, and sentinel changes; tools invalidate the cache.
- **Compaction** forces `getCache(true)` into `output.context`. Automatic consolidation queues through `client.session.prompt` with `noReply: true`, retaining agent/model/variant, so it never waits on its own active loop. SDK error responses retain native continuation; fallback prompts also resume pending work. Manual compaction and automatic user-message replay can bypass the continuation hook.
- **`consolidate_on_compact`** runs via `experimental.compaction.autocontinue`, which needs `client` captured from the factory's first arg (`input.client`) to call `client.session.prompt(...)`/`client.session.messages(...)`. It seeds the prompt from `fetchLatestCompactionSummary(sessionID)` (most recent assistant msg with `info.summary===true`; response unwrapped `res.data||res`) + a "resume pending work from Next Move" instruction, falling back to a full-scan `CONSOLIDATION_PROMPT` if no summary/fetch fails. Automatic compaction fires at `step-finish`, never mid-tool-call.
- **`experimental.compaction.autocontinue` does NOT fire on manual `/compact`** (upstream gates it on `input.auto`; manual defaults `auto:false`). So `consolidate_on_compact` only takes effect on automatic compaction. Manual-`/compact` consolidation is a known, not-planned gap.

## Testing

- `XDG_CONFIG_HOME` (→ temp dir) and `OCL_SHARED_MEMORY_HOME` must be set at the top of `smoke-test.mjs` BEFORE the plugin `import`s: `MEMORY_DIR`/`SHARED_MEMORY_DIR` are computed at module-load time, so order matters. Both plugin files import the SAME cached `ocl-memory-shared.mjs`, so `_carryOverChecked` is one shared instance across the process.
- State (`_cache`, `_requestCount`, `_carryOverChecked`, `_carryOverPending`) is process-global with no reset API; test order remains load-bearing.
- Config/index file changes refresh on the next cache check; memory tools invalidate immediately. Use `experimental.session.compacting({}, makeCompactOutput())` when a test explicitly needs a forced full refresh, not an injection-state reset.
- Cross-process lock tests wait for child IPC readiness, never a fixed startup sleep. The held-lock check expects at least 150 ms and below the 2 s shared window. Additional checks cover parallel OpenCode/OpenCode and OpenCode/pi writers, old-owner release, bounded failed reclaim, `EPERM`, busy refusal, migration retry, no-follow reads, atomic cleanup, and rollback. `test:host` uses a real isolated server and local fake model, not real model decisions or interactive TUI rendering.

## Releasing

- Version bump touches 3 files with NO single source of truth: `package.json` (`version`), `skills/memory/SKILL.md` (`version:` frontmatter), a new dated `## [X.Y.Z]` entry in `CHANGELOG.md`. Publish CI checks their consistency; verify locally before tagging. Current worktree version is 0.6.7.
- CI publishes on a `v*` tag push. `publish.yml` creates a GitHub release whose body is scraped from `CHANGELOG.md` by matching the `## [<version>]` heading — so the CHANGELOG heading MUST equal the tag version (minus the `v`). `NODE_AUTH_TOKEN` is set to `''` for OIDC Trusted Publishing; NEVER put a real token there.
- **CI gates the release:** `test.yml` runs `node --check` + `npm test` on every branch push and PR; `publish.yml` re-runs both plus a version-consistency check (tag == `package.json` == `SKILL.md` frontmatter == `## [version]` heading exists in CHANGELOG) BEFORE creating the GitHub release or publishing. Still run `npm test` and `node --check` locally before tagging — the gate exists to catch what you miss, not to be your first check.
